## 一、本地开发环境

### 前置条件

| 工具 | 版本要求 | 安装方式 |
|------|----------|----------|
| Python | 3.11+ | [python.org](https://www.python.org/downloads/) |
| Node.js | 18+ | [nodejs.org](https://nodejs.org/) |
| ffmpeg | 任意 | `brew install ffmpeg`（macOS） |
| git | 任意 | 系统自带或 brew |

```bash
# 验证环境
python3.11 --version   # Python 3.11.x
node --version         # v18.x.x
ffmpeg -version        # ffmpeg version x.x.x
```

---

### 1.1 克隆项目

```bash
git clone https://github.com/MDEWD/zhiyan-agent.git
cd zhiyan-agent
```

---

### 1.2 配置后端

```bash
cd backend

# 创建虚拟环境（必须用 Python 3.11）
python3.11 -m venv .venv
source .venv/bin/activate          # macOS / Linux
# .venv\Scripts\activate           # Windows

# 安装依赖（国内加镜像）
pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple

# 创建环境变量文件
cp .env.example .env
```

编辑 `backend/.env`：

```env
# ── 必填 ──────────────────────────────────────────────────────────────────────
DEEPSEEK_API_KEY=sk-xxxxxxxxxxxxxxxxxxxxxxxx
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-chat

# Obsidian 笔记保存路径（不使用 Obsidian 可填任意已存在的目录）
OBSIDIAN_VAULT=/Users/yourname/Documents/MyKnowledge/Videos

# ── 可选：LangFuse 可观测性（不填则静默跳过，功能不受影响）─────────────────────
LANGFUSE_PUBLIC_KEY=pk-lf-xxxxxxxx
LANGFUSE_SECRET_KEY=sk-lf-xxxxxxxx
LANGFUSE_BASE_URL=https://cloud.langfuse.com
```

---

### 1.3 启动后端

```bash
cd backend
source .venv/bin/activate
python app.py
# 服务运行在 http://localhost:8000
# 首次启动会下载 sentence-transformer 模型（约 500MB），需等待几分钟
```

验证后端正常：

```bash
curl http://localhost:8000/api/videos
# 返回 [] 即为成功
```

---

### 1.4 配置并启动前端

```bash
cd frontend
npm install
npm run dev
# 页面运行在 http://localhost:5173
```

前端通过 Vite 代理将 `/api/*` 请求转发到 `http://127.0.0.1:8000`，无需手动配置跨域。

## 二、生产部署（Railway）

Railway 是最简单的零配置云部署方式，免费额度足够个人使用。

### 2.1 准备工作

1. 注册 [Railway](https://railway.app) 账号（GitHub 登录）
2. Fork 本项目到你的 GitHub

---

### 2.2 部署后端

**方式一：通过 Railway 界面（推荐新手）**

1. Railway 控制台 → New Project → Deploy from GitHub repo → 选择本项目
2. 设置 Root Directory 为 `backend`
3. Railway 自动检测到 `requirements.txt` 并使用 Python buildpack

**方式二：添加 `railway.json`（推荐）**

在项目根目录创建 `railway.json`：

```json
{
  "build": {
    "builder": "NIXPACKS",
    "buildCommand": "cd backend && pip install -r requirements.txt"
  },
  "deploy": {
    "startCommand": "cd backend && python app.py",
    "healthcheckPath": "/api/videos",
    "restartPolicyType": "ON_FAILURE"
  }
}
```

**在 Railway 控制台设置环境变量：**

| 变量名 | 值 |
|--------|-----|
| `DEEPSEEK_API_KEY` | 你的 DeepSeek Key |
| `DEEPSEEK_BASE_URL` | `https://api.deepseek.com` |
| `DEEPSEEK_MODEL` | `deepseek-chat` |
| `OBSIDIAN_VAULT` | `/app/data/notes`（云端路径） |
| `PORT` | `8000` |
| `CHROMA_DB_PATH` | `/app/data/chroma_db` |
| `DATA_PATH` | `/app/data` |

**修改 `backend/app.py` 监听地址**（Railway 要求绑定 `0.0.0.0`）：

```python
# 文件末尾，将：
if __name__ == "__main__":
    uvicorn.run(app, host="127.0.0.1", port=8000)

# 改为：
if __name__ == "__main__":
    import os
    port = int(os.environ.get("PORT", 8000))
    uvicorn.run(app, host="0.0.0.0", port=port)
```

---

### 2.3 部署前端

前端需要知道后端的线上地址，通过环境变量注入：

**修改 `frontend/src/api/client.ts`**（第一行）：

```typescript
const BASE = import.meta.env.VITE_API_BASE ?? '/api'
```

**在 Railway 控制台创建第二个 Service，部署前端：**

1. New Service → GitHub Repo → 同一个仓库
2. Root Directory 设为 `frontend`
3. Build Command：`npm install && npm run build`
4. Start Command：`npx serve -s dist -l 3000`
5. 添加环境变量：`VITE_API_BASE=https://你的后端域名.railway.app/api`

> **更简单的方案**：让后端直接 serve 前端静态文件，见下方 §2.4。

---

### 2.4 前后端合并部署（推荐）

把前端构建产物嵌入后端，只需一个 Railway Service：

**第一步：前端构建**

```bash
cd frontend
VITE_API_BASE=/api npm run build
# dist/ 目录就是构建产物
```

**第二步：后端 serve 静态文件**

在 `backend/app.py` 中添加：

```python
from fastapi.staticfiles import StaticFiles
from fastapi.responses import FileResponse
import os

# 在所有 API 路由注册完成后，添加：
_FRONTEND_DIR = os.path.join(os.path.dirname(__file__), "..", "frontend", "dist")
if os.path.exists(_FRONTEND_DIR):
    app.mount("/assets", StaticFiles(directory=os.path.join(_FRONTEND_DIR, "assets")), name="assets")

    @app.get("/{full_path:path}")
    async def serve_frontend(full_path: str):
        index = os.path.join(_FRONTEND_DIR, "index.html")
        return FileResponse(index)
```

**第三步：`railway.json`**

```json
{
  "build": {
    "buildCommand": "cd frontend && npm install && npm run build && cd ../backend && pip install -r requirements.txt"
  },
  "deploy": {
    "startCommand": "cd backend && python app.py"
  }
}
```

这样只需一个服务、一个域名，前后端全在一起。

## 三、生产部署（Docker + 云服务器）

适合有自己服务器（阿里云/腾讯云/Hetzner 等）的场景，完全自主可控。

### 3.1 编写 Dockerfile

在项目根目录创建 `Dockerfile`：

```dockerfile
# ── Stage 1: 构建前端 ──────────────────────────────────────────────────────────
FROM node:18-alpine AS frontend-builder

WORKDIR /app/frontend
COPY frontend/package*.json ./
RUN npm ci

COPY frontend/ .
RUN npm run build


# ── Stage 2: 后端运行环境 ──────────────────────────────────────────────────────
FROM python:3.11-slim

# 系统依赖（ffmpeg 用于 Whisper）
RUN apt-get update && apt-get install -y \
    ffmpeg \
    && rm -rf /var/lib/apt/lists/*

WORKDIR /app

# 安装 Python 依赖（分层缓存）
COPY backend/requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

# 复制后端代码
COPY backend/ ./backend/

# 复制前端构建产物
COPY --from=frontend-builder /app/frontend/dist ./frontend/dist

# 数据目录
RUN mkdir -p /app/backend/data

WORKDIR /app/backend

EXPOSE 8000

CMD ["python", "app.py"]
```

---

### 3.2 编写 docker-compose.yml

在项目根目录创建 `docker-compose.yml`：

```yaml
version: "3.9"

services:
  app:
    build: .
    ports:
      - "8000:8000"
    environment:
      - DEEPSEEK_API_KEY=${DEEPSEEK_API_KEY}
      - DEEPSEEK_BASE_URL=${DEEPSEEK_BASE_URL:-https://api.deepseek.com}
      - DEEPSEEK_MODEL=${DEEPSEEK_MODEL:-deepseek-chat}
      - OBSIDIAN_VAULT=/app/data/notes
      - CHROMA_DB_PATH=/app/data/chroma_db
      - DATA_PATH=/app/data
      - LANGFUSE_PUBLIC_KEY=${LANGFUSE_PUBLIC_KEY:-}
      - LANGFUSE_SECRET_KEY=${LANGFUSE_SECRET_KEY:-}
      - LANGFUSE_BASE_URL=${LANGFUSE_BASE_URL:-https://cloud.langfuse.com}
    volumes:
      # 数据持久化：挂载到宿主机目录
      - ./data:/app/data
      - ./notes:/app/data/notes
    restart: unless-stopped
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:8000/api/videos"]
      interval: 30s
      timeout: 10s
      retries: 3
```

---

### 3.3 服务器部署步骤

**前提**：一台装有 Docker 的 Linux 服务器（Ubuntu 22.04 推荐）。

```bash
# 1. 安装 Docker（如果没有）
curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker $USER

# 2. 克隆项目到服务器
git clone https://github.com/MDEWD/zhiyan-agent.git
cd zhiyan-agent

# 3. 创建环境变量文件
cat > .env << 'EOF'
DEEPSEEK_API_KEY=sk-xxxxxxxxxxxxxxxxxxxxxxxx
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-chat
LANGFUSE_PUBLIC_KEY=pk-lf-xxxxxxxx
LANGFUSE_SECRET_KEY=sk-lf-xxxxxxxx
EOF

# 4. 构建并启动
docker compose up -d --build

# 5. 查看日志
docker compose logs -f app

# 6. 验证
curl http://localhost:8000/api/videos
```

---

### 3.4 配置 Nginx 反向代理（可选）

如果服务器已有 Nginx，配置域名访问：

```nginx
server {
    listen 80;
    server_name yourdomain.com;

    # 重定向到 HTTPS
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl;
    server_name yourdomain.com;

    ssl_certificate     /etc/letsencrypt/live/yourdomain.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/yourdomain.com/privkey.pem;

    # SSE 长连接必须关闭缓冲
    location /api/ {
        proxy_pass         http://127.0.0.1:8000;
        proxy_http_version 1.1;
        proxy_set_header   Connection "";
        proxy_set_header   Host $host;
        proxy_set_header   X-Real-IP $remote_addr;
        proxy_buffering    off;          # 关键：SSE 流式响应
        proxy_cache        off;
        proxy_read_timeout 300s;
    }

    # 前端静态资源（如果前后端分离）
    location / {
        proxy_pass http://127.0.0.1:8000;
    }
}
```

申请免费 HTTPS 证书：

```bash
sudo apt install certbot python3-certbot-nginx
sudo certbot --nginx -d yourdomain.com
```

## 五、数据持久化

### 本地开发

所有数据自动保存在 `backend/data/` 目录下，无需额外配置。

### Docker 部署

通过 `volumes` 挂载宿主机目录，容器销毁后数据不丢失：

```yaml
volumes:
  - ./data:/app/data    # 将宿主机 ./data 映射到容器内 /app/data
```

### 备份

```bash
# 备份所有数据
tar -czf backup_$(date +%Y%m%d).tar.gz data/

# 恢复
tar -xzf backup_20260101.tar.gz
```

### Railway 注意事项

Railway 的文件系统在每次重新部署时会重置，**数据会丢失**。

解决方案：
1. **Railway Volumes**（付费功能）：在 Service 设置中挂载持久化 Volume，路径设为 `/app/data`
2. **外部存储**：将 ChromaDB 替换为 Qdrant Cloud，将 JSON 文件替换为 PostgreSQL（适合认真使用）

## 六、常见问题

### Q1：首次启动很慢，卡在模型下载

首次运行会自动从 HuggingFace 下载两个模型：

| 模型 | 大小 | 用途 |
|------|------|------|
| `paraphrase-multilingual-MiniLM-L12-v2` | ~470MB | 文本嵌入 |
| `BAAI/bge-reranker-base` | ~280MB | 检索精排（首次搜索时下载） |

模型下载后缓存在 `~/.cache/huggingface/`，后续启动秒级完成。

国内网络慢时，可以设置镜像：

```bash
export HF_ENDPOINT=https://hf-mirror.com
python app.py
```

---

### Q2：端口被占用

```bash
# 找到占用 8000 端口的进程
lsof -i :8000

# 强制释放
kill -9 $(lsof -ti :8000)
```

---

### Q3：Bilibili 视频下载失败

Bilibili API 需要登录态。在 `.env` 中添加：

```env
BILIBILI_SESSDATA=你的SESSDATA
BILIBILI_BILI_JCT=你的bili_jct
```

获取方法：浏览器登录 B站 → F12 → Application → Cookies → 复制 `SESSDATA` 和 `bili_jct`。

---

### Q4：Docker 构建时安装 `torch` 超时

`openai-whisper` 依赖 PyTorch，镜像体积约 4GB。如果不需要 Whisper（所有视频都有字幕），可以注释掉 `requirements.txt` 中的 `openai-whisper`，镜像体积降至约 600MB。

---

### Q5：SSE 流式响应在 Nginx 后面中断

确保 Nginx 配置中包含：

```nginx
proxy_buffering    off;
proxy_cache        off;
proxy_read_timeout 300s;
proxy_http_version 1.1;
proxy_set_header   Connection "";
```

缺少 `proxy_buffering off` 是 SSE 不工作的最常见原因。

---

### Q6：Railway 部署后 API 返回 404

检查 `app.py` 中 uvicorn 的监听地址是否已改为 `0.0.0.0`：

```python
uvicorn.run(app, host="0.0.0.0", port=int(os.environ.get("PORT", 8000)))
```

Railway 通过 `PORT` 环境变量注入端口，默认值不一定是 8000。

---

### Q7：跨域错误（CORS）

`app.py` 已添加 CORS 中间件，默认允许所有来源。如需限制：

```python
app.add_middleware(
    CORSMiddleware,
    allow_origins=["https://yourdomain.com"],  # 替换为实际域名
    allow_methods=["*"],
    allow_headers=["*"],
)
```
